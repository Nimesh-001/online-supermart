# SuperMart Online — Member 3: Feature Documentation

## Real-Time Inventory Control, Stock Tracking, Low-Stock Triggers & Concurrency Decrement

- **Project:** SuperMart Online
- **Member:** Member 3
- **Features Implemented:**
  1. Real-Time Stock Tracking & Inventory Audit (`inventory` & `stock_movements`)
  2. Automated Low-Stock Alert Generation via Trigger `trg_check_low_stock` & `low_stock_alerts`
  3. Low-Stock Health & Reorder Reporting via Database View `v_low_stock_report`
  4. Operational Stock Replenishment via Stored Procedure `sp_add_stock`
  5. High-Concurrency Stock Decrement & Row-Lock Allocation via Stored Procedure `sp_atomic_stock_decrement` (`CallableStatement` OUT parameter with automatic rollback on insufficient quantity)
  6. Dynamic Stock Level Evaluation via Stored Function `fn_get_stock_status(quantity, min_threshold)`
  7. Automated Stock Movement Ledger Pruning via Scheduled Event `evt_prune_old_stock_movements`
- **Tech Stack:**
  - Frontend: React + Tailwind CSS (Vite) with real-time multi-tab Warehouse Stock Management dashboard
  - Backend: Java 21 + Spring Boot (JdbcTemplate, Strict Layered Architecture)
  - Database: MySQL 8.0+ (`online_supermarket`)
  - Architecture: `InventoryController` → `InventoryService` → `InventoryDao` → `JdbcTemplate` → `MySQL`

## 1. Database Artifacts Implemented & Utilized

Member 3 contributes **6 dedicated advanced database artifacts** across the database schema:

| Artifact Type | Name | Purpose |
| :--- | :--- | :--- |
| **Tables (3)** | `inventory`, `stock_movements`, `low_stock_alerts` | Tracks on-hand quantity, audit logs all stock delta reasons (`RESTOCK`, `SALE`, `ADJUSTMENT`), and holds automated alert notifications. |
| **View (1)** | `v_low_stock_report` | Joins `inventory`, `products`, `categories`, and `brands` to highlight items where `quantity_on_hand <= min_threshold`, calculating reorder deficits and stock values. |
| **Function (1)** | `fn_get_stock_status(p_qty, p_min_threshold)` | Categorizes stock into `'OUT_OF_STOCK'`, `'CRITICAL'`, `'LOW_STOCK'`, or `'HEALTHY'`. |
| **Trigger (1)** | `trg_check_low_stock` | `AFTER UPDATE` trigger on `inventory` that detects if stock dropped below threshold and inserts into `low_stock_alerts`. |
| **Procedures (2)**| `sp_add_stock`, `sp_atomic_stock_decrement` | `sp_add_stock` restocks products and appends to `stock_movements`. `sp_atomic_stock_decrement` uses `FOR UPDATE` pessimistic row lock with OUT status to prevent overselling under high concurrency. |
| **Event (1)** | `evt_prune_old_stock_movements` | Daily background maintenance event pruning resolved audit logs older than 180 days. |

## 2. API Endpoints (Member 3)

| Method | Endpoint | Auth Required | Description |
| :--- | :--- | :--- | :--- |
| `GET` | `/api/inventory` | Yes (Warehouse / Admin) | Fetches complete stock levels with dynamic status (`fn_get_stock_status`). |
| `GET` | `/api/inventory/low-stock` | Yes (Warehouse / Admin) | Queries database view `v_low_stock_report` for replenishment deficits. |
| `POST` | `/api/inventory/replenish` | Yes (Warehouse / Admin) | Restocks an item using stored procedure `sp_add_stock`. |
| `POST` | `/api/inventory/atomic-decrement` | Internal / Cart Service | Concurrency-safe atomic stock decrement using stored procedure `sp_atomic_stock_decrement`. |
| `GET` | `/api/inventory/movements` | Yes (Warehouse / Admin) | Retrieves chronological audit trail from `stock_movements`. |
| `GET` | `/api/inventory/alerts` | Yes (Warehouse / Admin) | Fetches automated alerts generated by `trg_check_low_stock`. |
| `PUT` | `/api/inventory/alerts/{id}/resolve`| Yes (Warehouse / Admin) | Marks a low-stock alert as resolved. |
