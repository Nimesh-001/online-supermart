# SuperMart Online — Member 6: Feature Documentation

## Executive Sales Analytics, Daily Reconciliation Batch, User Audit Triggers & Midnight Event Scheduler

- **Project:** SuperMart Online
- **Member:** Member 6
- **Features Implemented:**
  1. Executive Daily Sales Summaries & Aggregation (`daily_sales_summaries`)
  2. Enterprise Sales Overview via Database View `v_admin_sales_overview`
  3. Dynamic Daily Net Revenue Calculation via Stored Function `fn_get_daily_revenue(date)`
  4. Daily Sales Reconciliation Batch via Stored Procedure `sp_daily_sales_summary(date)`
  5. User Account Status Modification Audit Trail via Trigger `trg_audit_user_update` (writes JSON deltas to `audit_logs`)
  6. Midnight Automated Reconciliation via Scheduled Event `evt_midnight_sales_summary`
  7. Role-Based Dashboard Segregation between Super Admin (Executive) and Operational Manager (Fulfillment/Warehouse)
- **Tech Stack:**
  - Frontend: React + Tailwind CSS (Vite) with dedicated `SalesAnalyticsTab` and `AuditTrailTab`
  - Backend: Java 21 + Spring Boot (JdbcTemplate, Strict Layered Architecture)
  - Database: MySQL 8.0+ (`online_supermarket`)
  - Architecture: `AnalyticsController` → `AnalyticsService` → `AnalyticsDao` → `JdbcTemplate` → `MySQL`

## 1. Database Artifacts Implemented & Utilized

Member 6 contributes **6 dedicated advanced database artifacts** across the database schema:

| Artifact Type | Name | Purpose |
| :--- | :--- | :--- |
| **Tables (2)** | `daily_sales_summaries`, `audit_logs` | Stores reconciled daily financial summaries and security/audit trails with JSON deltas. |
| **View (1)** | `v_admin_sales_overview` | Projects `summary_date`, `completed_order_count`, `gross_sales`, `discounts_total`, and `net_sales` from `daily_sales_summaries`. |
| **Function (1)** | `fn_get_daily_revenue(date)` | Deterministic SQL function returning net sales for any target business date. |
| **Trigger (1)** | `trg_audit_user_update` | `AFTER UPDATE ON users` trigger that detects if `OLD.account_status <> NEW.account_status` and logs `JSON_OBJECT('status', OLD.account_status)` and `JSON_OBJECT('status', NEW.account_status)` into `audit_logs`. |
| **Procedure (1)** | `sp_daily_sales_summary(date)` | Batch procedure aggregating orders placed on `p_date` with duplicate key update on `daily_sales_summaries`. |
| **Event (1)** | `evt_midnight_sales_summary` | Scheduled background job running daily at midnight that automatically executes `CALL sp_daily_sales_summary(CURRENT_DATE())`. |

## 2. API Endpoints (Member 6)

| Method | Endpoint | Auth Required | Description |
| :--- | :--- | :--- | :--- |
| `GET` | `/api/analytics/sales-overview` | Yes (Super Admin) | Fetches executive sales summary from `v_admin_sales_overview`. |
| `GET` | `/api/analytics/daily-revenue` | Yes (Super Admin) | Dynamically computes net revenue for a date via `fn_get_daily_revenue`. |
| `POST` | `/api/analytics/reconcile` | Yes (Super Admin) | Runs batch reconciliation procedure `sp_daily_sales_summary`. |
| `GET` | `/api/analytics/audit-logs` | Yes (Super Admin) | Streams system audit trail generated by `trg_audit_user_update`. |
| `GET` | `/api/analytics/executive-kpis` | Yes (Super Admin) | Provides top-level KPI metrics (Gross, Net, Orders, Customers). |
